### Prerequisites

A Data Product should already exist in order to attach the new component to it.

### Creation Wizard

The Creation Wizard allows you to create a new Vast S3 Output Port.

#### Basic component information

This section covers the basic information that any component must have.

- Name: Required. The name of the component.
- Fully Qualified Name: Fully qualified name of the component.
- Description: Required. Help others understand what this output port is for.
- Domain: Required. Domain of the Data Product this output port belongs to.
- Data Product: Required. Data Product this output port belongs to.
- Identifier: Autogenerated from the information above. Not editable after creation.
- Component Owner: Automatically selected from the Data Product metadata.
- Depends On: An Output Port could depend on other output ports or storage areas.

#### Provide Output port deployment information

This section covers the physical location of the Vast S3 area backing this Output Port. All fields are required and are **not editable** after creation.

- S3 Path: Name of the S3 path.
- Policy Name: Name of the view policy to be used for the Vast view.
- Bucket Name: Name of the Vast S3 bucket.
- Vip Pool: Name of the Vast Vip Pool.

#### Creation

After this step, the system will show you the summary of the information provided. You can go back and edit them if you notice any mistake, otherwise you can go ahead and create the component.

After clicking on **"Create"**, the component registration will start. If no errors occur, it will go through the 3 phases (Fetching, Publishing and Registering) and it will show you the links to the newly created repository inside GitLab and the new Data Product component in the Builder Catalog.

When deploying the Data Product, deployment of this component will make the specified S3 area available at the given path.

### Editing

Once the component has been created, additional descriptive metadata can be filled in or updated at any time using the **Edit** wizard, without touching the physical deployment information:

- Process Description, Interval of Change, Timeliness, Up Time, Terms and Conditions, Endpoint
- Data Sharing Agreements: Purpose, Billing, Security, Intended Usage, Limitations, Life Cycle, Confidentiality
